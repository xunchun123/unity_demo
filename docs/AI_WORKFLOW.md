# AI 辅助开发流程：《勇者远征》是怎么做出来的

> 代码初稿主要由 AI 生成。我负责拆需求、定架构约束、选素材、审查代码、进游戏验证。这和 JD 里"AI 辅助开发并能审查 AI 代码"的要求是对应的：AI 是受控的生产力工具，产出质量由人负责。

## 分工

| 环节 | AI | 我 |
| --- | --- | --- |
| 需求拆解 | — | 把"改成好看的横版动作游戏"拆成：像素美术管线 → 勇者动画 → 怪物动画 → 环境 → 机关 → 文档，一次只做一块 |
| 架构约束 | 按约束实现 | 定规则：timeScale 只许 GameManager 改；Animator 是 sprite 唯一写入者；怪物 AI 只在状态切换处写动画参数；全项目一个 PPU |
| 素材 | 切帧、对齐、生成剪辑 | 选画风（统一用 ansimuz 的 Gothicvania 系列，CC0），定每个怪物对应哪套素材 |
| 编码 | 写初稿 | 审查：API 版本、生命周期、GC、事件订阅、空引用、timeScale 纪律 |
| 验证 | 在编辑器里自动试玩、截图、连拍 | 看截图判断"对不对、好不好"，定位问题，决定怎么改 |

## 工作循环

1. **一次只改一个系统**：比如"三职业共用一张状态机"，先写清楚状态、参数、过渡规则、验收标准，再让 AI 实现。
2. **编译**：读编译日志，0 error 才往下走。
3. **进游戏验证**：Play 模式下模拟按键、传送角色、读写字段，开 0.25 倍慢动作逐帧连拍。看的是动作有没有播完整、出招点对不对、朝左朝右是否一致、伤害数字对不对。
4. **定位并修复**：截图不对就回到代码找原因，修完重跑同一套验证。
5. **按功能提交**：一个功能一次提交，提交说明写"改了什么 + 为什么"。
6. **沉淀约束**：审查发现的问题写成新的约束，比如"范围判定要考虑一个对象有多个碰撞体"，后面的代码都照这个检查。

本地验证用的是一个编辑器内的文件指令桥（只在本机，不入库）：外部写指令文件，编辑器脚本读取后执行"编译 / 一键搭建 / 进入 Play / 模拟按键 / 调用方法 / 截图"，结果和 Console 日志写回文件。截图目录 `docs/screenshots/` 里的图就是这样截的。

## 审查清单

| 检查项 | 重点 |
| --- | --- |
| API 版本 | 只用 2022.3 里有的 API（`FindFirstObjectByType` 而不是过时的 `FindObjectOfType`），新 Input System 写法 |
| 生命周期 | 单例 Awake 去重 + OnDestroy 清引用；OnEnable / OnDisable 成对订阅；隐藏对象的 OnEnable 不会执行 |
| timeScale | 除 GameManager 和命中停帧外不许写；timeScale = 0 时所有用 deltaTime 做除法的地方要检查 |
| 碰撞 | 一个对象可能有多个碰撞体；Trigger 不能当地面；实体碰撞体之间不产生 Trigger 事件 |
| 写入者唯一 | sprite 只由 Animator 写；速度在同一帧不能被两个系统改 |
| 像素美术 | 不能非整数缩放；统一 PPU；pivot 统一在脚底 |

## 审查和验证中抓到的真实问题

**1. 每一刀打了两次伤害。**
验证时用调试指令读怪物血量：长剑一刀 20，地狱犬 90 血，砍一刀掉了 40。原因：怪物有实体碰撞体和接触伤害 Trigger 两个碰撞体，`OverlapBoxAll` 把同一只怪扫到两次。修复：`EnemyBase.TakeDamage` 对同一帧、同来源、同数值的伤害去重。这也是"怪一下就没了"的一半原因。

**2. 受击闪白完全没效果。**
AI 初稿写的是 `sr.color = Color.white`。SpriteRenderer 的 color 是乘法染色，白色 × 原图 = 原图，等于没闪。修复：新增 `SpriteFlash`，叠一层用 GUI/Text Shader 的纯色剪影（只取贴图 alpha，颜色全来自顶点色），在 LateUpdate 里同步当前帧和翻转。

**3. 击退被吃掉。**
怪物 AI 每一帧都会重写 `rb.velocity`，击退刚加上就被覆盖。修复：小怪受击后硬直 0.22 秒，期间 AI 暂停、速度自然衰减；精英和 BOSS 设为霸体，只闪光不硬直，用击退抗性控制推动幅度。

**4. 攻击动画卡在最后一帧。**
脚本创建的 Exit 过渡默认 `hasExitTime = false`，又没有任何条件，Unity 会直接忽略这条过渡。修复：一次性动作的退出过渡显式设置 Exit Time = 1。

**5. 暂停后相机整关卡死。**
控制台一次刷出九百多条 "transform.position 是 NaN"。原因：timeScale = 0 时 `Mathf.SmoothDamp` 在 deltaTime = 0 且已经到达目标的情况下会计算 (output − target) / deltaTime = 0/0，速度变量变成 NaN，之后每帧都是 NaN。修复：deltaTime 为 0 时不推进，并清掉被污染的速度变量。

**6. 火铳子弹从背后飞出。**
连拍发现朝左开火时子弹从人物背后生成。原因：出招点是固定的本地坐标，转身只翻转了贴图，没有镜像出招点。修复：出招点按职业配置（剑刃、拳头、枪口高度不同），朝向改变时镜像 x。

**7. 改文案后中文显示成方框。**
TMP 静态图集只有烘焙过的字，新文案里的"铳""掌"不在字表里。修复：搭建时自动扫描脚本里显示给玩家的字符串，缺的字原地补进图集，资产 GUID 不变，场景里的字体引用不会断。

## 一句话总结

> AI 负责把说清楚的需求变成能编译的代码；我负责把需求说清楚、守住架构约束、按清单审查、进游戏验证。上面七个问题，没有一个是编译器能发现的。
